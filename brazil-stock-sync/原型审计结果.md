# 现有原型审计结果

审计对象：`inventory_pipeline.py`、`server.py`、`tests/test_inventory_pipeline.py`

## 已验证通过

- SKU 重复销售数据可以按 SKU 汇总。
- 平台店铺销量可以按 SKU + 店铺维度汇总。
- 缺失销售数据默认补 0。
- 未匹配产品会生成 warning，不会自动猜 SKU。
- 重点店铺 J/K/L 会重新写入公式。
- 工作簿会设置自动计算、打开时全量重算。
- 原文件读取后生成新文件，不直接覆盖上传的原始文件。
- 现有 10 项单元测试全部通过。

## 已完成的修正

### 1. OMS 重复 SKU 汇总

已改为按 SKU 汇总 `已锁`、`可用库存` 和 `不良品数`，不会再出现后一个仓库记录覆盖前一个仓库记录的情况。

### 2. W 列不再重复扣除待开票

已改为：

```text
U = 待开票数量
W = OMS 可用库存
```

并新增回归测试验证。

## 仍需处理的问题

### 1. 店铺名称需要配置化

当前店铺名称映射写在代码常量中。第一版可以保留默认映射，但最终应移到配置文件，以便新增店铺时不修改程序。

### 2. 产品到 SKU 的匹配需要异常分层

目前按“产品名称 → 装柜跟踪表 SKU”精确匹配。建议保留三种结果：

- 精确匹配：自动更新；
- 去空格后匹配：自动更新并记录清洗动作；
- 无法匹配：只进异常清单，不写入。

不建议按模糊产品名自动匹配，因为同一产品可能有颜色、规格或变体差异。

### 3. 原型 README 需要重新编码

当前 README 在 PowerShell 输出中显示为乱码。代码和测试实际可以运行，但交付给同事时必须统一使用 UTF-8，避免使用说明无法阅读。

## 修正优先级

1. 增加 SKU 匹配分层报告；
2. 统一 README 和页面中文编码；
3. 再接入 Playwright。

## 结论

现有原型可以作为数据引擎基础继续使用，但暂时不应直接用于正式更新 Stock_Order。库存汇总逻辑已通过单元测试和干跑验证，剩余工作集中在异常分层、中文编码和网页自动抓取。
