# UpSeller / OMS 自动化连接器说明

## 当前状态

- Playwright Node 运行时可用。
- 页面识别、登录状态识别和导出按钮选择已经有离线测试。
- 现有数据处理引擎已能接收标准化导出文件。
- 实际浏览器探针在站点加载或 DOM 读取阶段超时，暂未执行导出操作。

## 连接器原则

1. 验证阶段优先读取用户已经登录的浏览器标签页；最终 `.exe` 使用程序自己的持久化浏览器配置目录，首次由同事登录一次，后续自动复用。
2. 不读取密码、Cookie、LocalStorage 或令牌。
3. 页面加载不以整页 network idle 为成功条件，只等待目标表格或导出控件出现。
4. 每一步使用页面可见文本、稳定属性或表格列名定位，不使用固定坐标。
5. 连接器有明确超时，超时后保存当前页面、URL、标题和步骤名称并退出。
6. 只在用户点击“抓取并预览”后执行导出；不会自动提交采购或修改库存。

## UpSeller 流程

1. 进入产品销量页面。
2. 选择北京时间对应的业务日期范围。
3. 确认平台和店铺筛选为全部，或按配置映射到指定店铺。
4. 等待产品销量表格出现。
5. 点击唯一的“导出”按钮。
6. 等待下载事件完成。
7. 校验文件包含 `SKU`、`店铺`、`销量` 等字段。
8. 交给本地数据引擎聚合。

## OMS 流程

1. 进入库存清单页面。
2. 等待库存表格出现。
3. 导出库存清单。
4. 识别 `商品SKU`、`已锁`、`可用库存`、`不良品数` 等列。
5. 按 SKU 汇总多仓库记录。
6. 如启用效期校验，再导出效期明细。

## 失败处理

| 失败类型 | 处理 |
|---|---|
| 未登录 | 返回“请在对应网站登录” |
| 页面加载超时 | 返回系统名称、当前 URL、步骤和超时原因 |
| 找不到目标表格 | 保留页面现场，不点击猜测控件 |
| 找不到导出按钮 | 返回页面标题和可见操作区域 |
| 下载超时 | 不进入数据处理，不生成更新文件 |
| 文件字段不完整 | 进入异常报告，不更新 Stock_Order |

## 当前技术结论

浏览器连接层需要改为“目标元素等待”的方式，不能直接依赖整页导航完成。独立 Playwright 进程不能直接共享用户 Chrome 的登录态，因此 `.exe` 要维护自己的持久化登录目录。待页面探针稳定后，再实现真正的下载按钮操作。
# Chrome 登录复用方式

程序默认通过本机 Chrome 调试端口复用已经登录的 OMS 和 UpSeller，不再创建第二套登录档案。

首次使用时需要关闭所有 Chrome 窗口，再用下面方式启动 Chrome；登录一次后，后续运行程序会复用该登录状态：

```powershell
& 'C:\Program Files\Google\Chrome\Application\chrome.exe' `
  '--remote-debugging-port=9222' `
  '--user-data-dir=C:\Users\USER\Documents\巴西库存更新自动化平台搭建\runtime\chrome-user-data'
```

然后在这个 Chrome 中登录 OMS 和 UpSeller。程序连接地址默认为 `http://127.0.0.1:9222`，也可以通过环境变量 `BRAZIL_STOCK_CDP_ENDPOINT` 修改。

注意：Chrome 必须以调试端口方式启动，普通已经打开的 Chrome 不能被外部 `.exe` 安全接管，这是 Chrome 的安全限制。
