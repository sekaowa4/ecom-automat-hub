# 巴西库存更新自动化平台

## 1. 当前结论

平台采用“自动抓取 → 数据校验 → 预览 → 人工确认 → 更新 Stock_Order”的流程。

本地导出的 Excel 只作为数据源，不作为最终业务逻辑载体。Stock_Order 中已有的公式必须保留，自动化程序只更新输入列和数据源表，避免覆盖公式。

最终形态：Windows 桌面 `.exe`，同事打开后点击“抓取并预览”，确认无误后点击“更新 Stock_Order”。

## 2. 数据来源

| 来源 | 主要用途 | 自动化方式 |
|---|---|---|
| UpSeller 产品销量 | 3/7/15/30 天销量、平台店铺销量 | Playwright 登录后选择日期并导出 |
| OMS 库存清单 | 第三方锁定、不良品、可用库存、在途库存 | Playwright 登录后导出 |
| OMS 效期明细 | 效期和过期库存辅助校验 | Playwright 导出，必要时启用 |
| UpSeller/Full 库存 | Meli Full 各店铺库存 | Playwright 导出 |
| 待开票数据 | 待开票数量 | 企业微信文档或导出文件读取 |
| 装柜到仓时间跟踪表 | SKU、备货总计、在途、下一批到货天数 | Stock_Order 内部数据源 |
| 采购成本 | SKU 对应采购成本 | Stock_Order 内部数据源 |

## 3. Stock_Order 字段规则

### 3.1 自动写入的输入列

| Stock_Order 列 | 来源/处理规则 |
|---|---|
| P-S Meli Full 店铺库存 | Full 库存按 SKU 和店铺归集；写入对应店铺的可用库存 |
| T 第三方锁定库存 | OMS `已锁` 按 SKU 汇总 |
| U 待开票 | 待开票数据按 SKU 汇总 `产品数量` |
| V 不良品数 | OMS `不良品数` 按 SKU 汇总 |
| W 第三方可用库存 | OMS `可用库存` 按 SKU 汇总 |
| Z-AC 3/7/15/30 天 | 对应销售周期导出的 `销量` 按 SKU 汇总 |
| AI-AS 各平台店铺销量 | 销售数据按 SKU、平台、店铺归集 |

### 3.2 必须保留的公式列

以下列默认不由程序直接改值：

`B SKU`、`J-L 重点店铺`、`X 总库存`、`Y 在途`、`AD 加权平均日销`、`AE 可售天数`、`AF 库存覆盖差值`、`AG 状态`、`AH 提价建议`、`AT 国内补货建议`、`AU 国内补货数量`、`AX 安全库存系数`、`AZ 采购成本`、`BA 总在库价值`、`BD 总在途价值`。

其中：

- `B SKU` 由“装柜到仓时间跟踪表”按产品查找生成；不能根据产品名直接硬编码。
- `J-L 重点店铺` 根据各平台店铺销量公式计算；程序只写销量输入列。
- `X` 根据 `P:W` 计算；程序不直接写总库存。
- `AD:AH` 和 `AT:AU` 是业务判断结果；程序只负责让其依赖的数据完整、类型正确。

## 4. 数据清洗与匹配规则

### SKU

匹配优先级：

1. 精确匹配 SKU；
2. 去除首尾空格后匹配；
3. 统一大小写后匹配；
4. 仍无法匹配时进入异常清单，不自动猜测。

### 店铺名称

系统建立固定映射表，把销售导出中的完整店铺名称映射成 Stock_Order 的简名，例如 `店铺1`、`店铺2`、`店铺3`、`店铺6`。店铺映射不写死在代码里，放在配置文件中，方便后续新增店铺。

### 数值

- 空值按 0 处理，但原始文本保留在运行记录中；
- 数字中的逗号、货币符号和千位分隔符统一清理；
- 库存、销量、订单量使用整数；
- 金额保留两位小数；
- 不允许把 `#N/A`、`#VALUE!` 等错误文本写入输入列。

### 日期

- 运行日期使用北京时间；
- 巴西时间只用于展示运行时间和日志，不改变业务日期；
- 同一次运行的所有来源文件必须记录下载时间、业务日期和文件名；
- 如果源文件日期不同，预览页明确标出“数据日期不一致”，但不擅自混合隐藏处理。

## 5. 运行流程

```text
点击“抓取并预览”
        ↓
打开/复用 UpSeller 和 OMS 登录会话
        ↓
按固定日期和筛选条件导出数据
        ↓
读取企业微信文档或本地配置数据
        ↓
标准化 SKU、店铺、数值和日期
        ↓
按 SKU 聚合并生成待更新数据集
        ↓
检查重复 SKU、未匹配 SKU、空值、日期差异
        ↓
展示预览和异常清单
        ↓
点击“确认更新 Stock_Order”
        ↓
备份原文件/原表 → 只更新输入列 → 重新计算公式
        ↓
生成运行日志和结果报告
```

## 6. 稳定性设计

- UpSeller、OMS 使用 Playwright，但不依赖固定坐标；通过文字、表格列名和按钮语义定位。
- 每个站点单独封装为连接器，页面变化时只修改该连接器。
- 登录态保存在本机安全目录，首次使用由同事手动登录，后续自动复用。
- 每次写入前自动备份 Stock_Order。
- 写入失败时保留导出文件、预览数据和错误日志，不覆盖原数据。
- 对公式列做写前快照和写后检查，检测公式是否被替换成普通值。
- 程序不自动提交采购、不自动发送外部消息，只更新库存分析表。

## 7. 页面设计

首页包含：

- 公司标识：厦门众赢未来科技有限公司；
- 北京时间 / 巴西时间；
- 上次运行时间、数据日期、运行状态；
- “抓取并预览”按钮；
- “确认更新 Stock_Order”按钮；
- 运行日志、异常数量和数据源状态。

预览页至少显示：

- 更新行数；
- 成功匹配 SKU 数；
- 未匹配 SKU 数；
- 重复 SKU 数；
- 各平台库存和销量汇总；
- 日期不一致警告；
- 更新前后关键列对比。

## 8. 分阶段开发顺序

### 阶段一：数据引擎

先用现有导出文件完成读取、清洗、匹配、聚合和预览，不接网页自动化。

验收标准：相同输入文件下，结果可重复；所有异常都有清单；不修改原始文件。

### 阶段二：UpSeller 和 OMS 抓取

用 Playwright 实现登录态复用、日期筛选、导出、下载文件识别和失败重试。

验收标准：不手动选择文件，点击一次即可得到标准化数据包。

### 阶段三：Stock_Order 更新

优先写入机器人创建且可编辑的企业微信目标表；如果继续使用本地/WPS 文件，则使用保留公式和样式的安全写入方式。

验收标准：输入列更新正确，公式列仍是公式，重点店铺和补货建议正常显示。

### 阶段四：桌面端和 `.exe`

加入配置、日志、备份、权限提示和打包安装流程，最后再分发给同事。

## 9. 当前明确的技术边界

企业微信 MCP 的“编辑文档内容”能力本身存在，但能否编辑取决于文档的创建者、文档类型和机器人对该文档的授权范围。机器人创建的普通文档已验证可以编辑；成员创建的表格/智能表格可能返回无权限。因此平台第一版不把企业微信作为唯一写入通道，而是保留本地 Stock_Order 和机器人创建的目标表两条路径。

这能保证平台不会因为某一份文档权限变化而整体停摆。
