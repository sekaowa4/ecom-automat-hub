# 企业微信智能表格写回设计

## 目标

将工作台的库存计算结果，在用户确认后按 SKU 写回企业微信 Stock 智能表格的“订单库存总表”。

## 边界与安全

- 工作台不会在导出或预览阶段写入企业微信。
- 写回前重新读取智能表格记录，用 SKU 建立 `record_id` 映射。
- 仅更新库存、销量和关联的计算输入字段；未匹配 SKU 跳过并保留原值。
- 每批最多 500 条记录，返回成功、跳过和失败的明细。
- MCP 地址为本机私密配置，不写入源码、日志或可分享的安装包。

## 连接与数据流

1. 用户在“系统设置”粘贴企业微信机器人 Streamable HTTP MCP 地址和 Stock 智能表格链接。
2. 本地服务通过 MCP 调用 `smartsheet_get_sheet`、`smartsheet_get_records` 和 `smartsheet_update_records`。
3. 工作台从本次导出的 7 个文件计算 SKU 更新值，先生成只读预览副本。
4. 用户确认后，服务分页读取“订单库存总表”，按 SKU 找到 `record_id`，分批调用更新接口。
5. UI 显示实际写回数量、跳过的未匹配 SKU 和失败原因，并保留运行日志。

## 字段策略

智能表格字段名作为写回键：`3天`、`7天`、`15天`、`30天`、`店铺1` 至 `店铺23`、`第三方锁定库存`、`第三方可用库存`、`不良品数`、`待开票`。字段不存在时不写入，并在结果中报告，不猜测字段。

## 验证

- 单元测试覆盖 SKU 到 record_id 映射、未匹配跳过、500 条分批和缺失字段跳过。
- 连接测试仅使用读取工具。
- 真正写回必须由界面“确认回写”触发。
