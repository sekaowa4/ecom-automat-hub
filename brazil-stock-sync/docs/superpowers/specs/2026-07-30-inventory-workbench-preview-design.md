# 库存自动化工作台预览界面设计

## 目标

制作一个可在浏览器中查看的 HTML 原型，展示最终 `.exe` 平台的核心流程：点击一次自动抓取数据，生成库存更新预览，用户确认后才回写企业微信。

## 用户流程

1. 用户打开平台首页，看到北京时间、最近运行记录和数据源连接状态。
2. 用户点击“开始今日库存更新”。原型用本地模拟状态展示 OMS、企业微信表格、销售数据的抓取进度。
3. 抓取完成后进入“更新预览”，展示本次涉及的 SKU 数量、重点补货项、库存覆盖天数、补货建议和异常项。
4. 用户点击“确认回写”后显示成功状态；点击“取消本次更新”则返回首页，不改变任何数据。
5. 原型保留“下载备份”和“查看运行日志”入口，体现正式平台的可追溯性。

## 页面结构

- 左侧导航：运行概览、更新预览、运行日志、系统设置。
- 顶部栏：产品名、北京时间、连接状态、用户菜单。
- 概览区：主操作按钮、上次运行摘要、数据源状态列表。
- 预览区：摘要统计、变更表格、异常提示、确认/取消动作。
- 日志抽屉：按步骤显示抓取、计算、预览和回写状态。

## 视觉方向

- 面向内部运营人员，采用清晰、稳重、低装饰的工作台风格。
- 深蓝色侧栏和浅灰背景，绿色表示成功，橙色表示待确认，红色表示异常。
- 以表格和状态行承载信息，不使用大量装饰性卡片。
- 主按钮始终强调“开始今日库存更新”或“确认回写”，避免误操作。

## 原型边界

- 本次只实现前端静态 HTML/CSS/JavaScript 预览，不接入真实 OMS 或企业微信 API。
- 使用模拟数据和短暂进度动画验证页面流程。
- 不执行真实回写；“确认回写”只展示模拟成功结果。
- 后续接入真实 API 时，保留 `startRun`、`loadPreview`、`confirmWriteback` 三个清晰的替换点。

## 验收标准

- 首页不出现“手动上传文件”作为主流程。
- 点击主按钮后能看到抓取进度，并自动进入预览页。
- 预览页能看到变更数量、SKU、库存、可售天数、状态、补货建议和异常信息。
- 取消不会进入回写成功状态；确认会显示回写成功状态。
- 页面在桌面浏览器宽度下可读，并在窄屏下不发生横向溢出。
