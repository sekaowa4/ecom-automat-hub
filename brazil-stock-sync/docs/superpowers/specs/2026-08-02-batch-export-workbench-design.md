# 一键批量导出与库存预览设计

## 目标

工作台点击一次“开始今日库存更新”后，复用已登录的 Chrome，按固定顺序完成 UpSeller 与 OMS 的 7 个文件导出，显示每一步状态，并让库存预览直接读取本次导出的文件。

## 范围

- 包含：7 个文件的顺序导出、北京时间日期范围、文件命名、任务状态、失败信息、预览读取。
- 不包含：企业微信写回、真实回写确认、`.exe` 打包。

## 文件顺序

1. 近30天销售数据.xlsx
2. 近7天销售数据.xlsx
3. 近15天销售数据.xlsx
4. 近3天销售数据.xlsx
5. FULL库存数据.xlsx
6. 库存数据.xlsx
7. OMS库存数据.xlsx

## 架构

浏览器自动化仍由 `automation/batch_export.js` 负责，服务端创建一个本地任务并保存任务状态 JSON。前端通过任务 ID 轮询状态，展示每个文件的等待、进行中、完成或失败状态。任务全部成功后，预览接口把 `runtime/portal-downloads` 作为本次运行的数据源，避免把旧的 `D:/Mic` 文件误当成最新数据。

任务失败时保留已经成功的文件，不自动覆盖或清理，返回失败步骤、错误信息和已生成文件列表。

## 验收标准

- 前端一次点击只创建一个批量任务。
- 7 个步骤按顺序执行，文件名严格匹配。
- 自定义销售区间以北京时间计算，结束日为昨天，不包含当天。
- 页面能看到每个步骤的实时状态与失败原因。
- 7 个步骤全部成功后，库存预览读取本次导出的文件。
- Node 与 Python 现有测试全部通过，并新增任务状态/路径测试。
