# 巴西库存更新自动化平台设计

## 目标

构建一个本地网页 MVP：用户选择 7 份源 Excel 和 `Stock_Order.xlsx`，点击运行后，系统按 SKU/店铺汇总数据、回填目标表、执行校验，并下载更新文件与异常报告。

## 已确认规则

- 每天运行一次，按北京时间处理，包含当天。
- SKU 匹配不到时留空。
- 重复 SKU 自动汇总。
- 30 天总销量包含全部店铺；两个 physical 店铺计入总销量，但不单独写入店铺列。
- 严重校验失败时不生成最终更新文件。
- 原始文件只读，不覆盖。

## 数据映射

| 目标列 | 数据来源 | 规则 |
|---|---|---|
| P-S | FULL 库存 | Meli 店铺 1/2/3/6 的 SKU 可用库存汇总 |
| T | OMS | 已锁库存 |
| U | 待开票 | SKU 产品数量汇总 |
| V | OMS | 不良品数 |
| W | OMS + 待开票 | 可用库存减待开票数量 |
| Z-AC | 近 3/7/15/30 天销售 | SKU 销量汇总 |
| AI-AS | 销售数据 | 11 个线上店铺按 SKU、店铺汇总 |

## 架构

采用本地 Python 服务 + 浏览器页面。后端负责读取/解析 XLSX、生成结果文件和校验报告；前端负责文件选择、运行状态、结果摘要和下载。XLSX 通过 OOXML 级别处理，尽量保留原始 `Stock_Order` 的样式、公式和工作表结构。

## 校验

- 必需文件是否齐全。
- 必需表头是否存在。
- 源文件是否有数据行。
- 销售店铺是否属于已配置店铺或 physical 店铺。
- 目标 SKU 是否能匹配；未匹配 SKU 进入警告，不填 0。
- 每个源文件的原始数量总和与汇总后数量总和一致。

## 非目标

第一版不自动登录 OMS/UpSeller，不直接写企业微信文档；先完成文件上传、处理、下载闭环。
