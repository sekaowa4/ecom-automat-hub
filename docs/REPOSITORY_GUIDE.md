# 仓库维护指南 / Repository Guide

本仓库采用**一个仓库、多个独立项目目录**的方式管理自动化工具。统一的是项目导航与协作约定，**不强行统一不同项目的运行环境、依赖、目录结构或部署方式**。

## 目录与命名

- 已存在的 `brazil-stock-sync/`、`mercado-livre-auth-mailer/` **保持原名、原路径**。
- 新项目名称建议使用英文小写加连字符，例如 `meli-repricing/`、`sales-daily-report/`；**这些只是命名示例，目前不代表该目录存在**。
- 每个项目维护自己的 `README.md`、源码、依赖、测试和 `.gitignore`；可以根据需要增加 `AGENTS.md` 与项目级 `docs/`。
- 仓库首页只保留概览，较详细的入口和运行限制写入 [PROJECTS.md](PROJECTS.md)，具体使用方法仍归各项目 README。

## 新项目接入检查表

- [ ] 源码属于允许备份 / 发布的范围，已确认仓库可见性是否合适。
- [ ] 新增独立目录，未覆盖已有项目，也未修改原有定时任务依赖的路径。
- [ ] 增加 README，说明功能、运行入口、安装和配置步骤、测试方法、限制。
- [ ] 提供示例配置，真实配置留在本机；排除凭据、业务数据、日志、浏览器会话、虚拟环境和构建产物。
- [ ] 审查即将提交的所有文件内容、文件名、差异和 Git 历史，确认没有 Token、Cookie、Webhook、个人或公司敏感信息。
- [ ] 只运行与变更相关的**安全检查**；不得为了维护仓库执行正式库存写回、发送邮件或企微通知。
- [ ] 更新仓库首页及 PROJECTS.md，并核对相对链接。
- [ ] 同步前确认远端最新提交，保留其他项目的变化；提交完成后回读仓库文件树和提交记录。

## 手机 ChatGPT 与电脑 Codex 的协作

1. **开始工作前：** 先检查 GitHub 对应分支的最新代码，确认本地项目和远端是否有未同步变更。
2. **修改与验证：** 在目标项目内做最小必要修改；视变更范围执行测试。未执行的测试必须明确说明。
3. **脱敏与同步：** 遵循该项目自己的 `AGENTS.md` 和同步规范。库存项目特别要求先生成**脱敏快照**，不得直接发布工作目录。
4. **提交保护：** 只更新属于本次任务的文件；保留其他人的提交；不强制推送。若分支在此期间变化，先重新核对差异。
5. **运行 / 部署：** GitHub 上的提交不等于公司电脑已拉取或部署。运行前仍需本机配置与验证。

> **注意：** Codex、ChatGPT 和 GitHub 不会因为修改了某个本地文件就自动完成双向同步。一次同步是否成功，必须以远端实际提交为依据。

## 信息安全

当前仓库为公开可见。对于尚未确认可以公开的公司业务源码，优先使用 Private 仓库或暂停上传；不要把“已脱敏”误认为“完全安全”。

`.gitignore` 仅影响通常的 Git 未跟踪文件匹配行为，不能抹去过去上传的敏感内容。如果凭据误入提交，需要进行凭据撤销 / 轮换和历史审查，不要只删除文件。

## 文档维护原则

- 不根据代码存在就声称功能已上线、正在运行或测试通过。
- 对有已知失败的测试如实标注，不通过修改描述掩盖问题。
- 若项目路径需要迁移，先评估 Windows 计划任务、快捷启动脚本、文件路径、自动同步范围和 README 内链接，再实施迁移。
