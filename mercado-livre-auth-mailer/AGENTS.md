# 工作原则

- 编码前先核对证据，说明影响结果的假设和取舍。
- 使用解决当前问题所需的最小实现，不加入未要求的功能。
- 只修改任务涉及的文件，保留用户已有改动。
- 以可验证的结果完成任务，不能把预期结果当成已验证结果。

# GitHub 同步约定

用户已要求本项目后续修改同步到 GitHub，无需为同一范围的同步重复请求许可。

- 仓库：`sekaowa4/ecom-automat-hub`，分支：`main`。
- 本项目在仓库中的目录：`mercado-livre-auth-mailer/`。
- 当前运行文件夹保留原位置，避免影响 Windows 定时任务。仓库的本机副本位于桌面 `ecom-automat-hub` 文件夹；两个文件夹不是实时关联的。
- 每次完成项目修改后，先执行与修改相关的检查，再将变更和文件删除同步到上述云端目录。同步前读取最新远端版本，保留其他项目和别人提交的更改，不强制覆盖分支。
- 普通 Git 推送不可用时，使用已连接的 GitHub 工具批量创建提交，并校验预期分支头。不要将访问令牌写入文件或命令。
- 同步完成后更新本机仓库副本，并对照远端提交核验本项目源码；确认成功后才能向用户报告已同步。若同步失败，明确报告未同步状态。
- 同步范围：`shop_auth_codes/*.py`、`tests/*.py`、`tools/*.py`，以及根目录的 `.gitignore`、`AGENTS.md`、`README.md`、`requirements.txt`、`config.example.toml`、`template.txt` 和现有 `.ps1` 脚本。新增文件需确认属于项目源码且无敏感数据，才能纳入同步。
- 禁止上传 `config.toml`、凭据、邮箱密码、客户端授权码、企微 webhook 密钥、真实店铺授权码、浏览器 cookie/登录会话、`profiles/`、`runtime/`、`data/`、`.venv/`、缓存以及原始 Word 文档。不得为了同步而清除这些本机运行数据。
- GitHub 同步和测试不授权发送业务邮件、发送企微通知或重新采集店铺授权码。只有用户要求补发或运行既定业务任务时才执行这些操作。
