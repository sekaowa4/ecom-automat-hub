# 混合调价固定流程

0.4.12支持整表按每店实时价格判断降价、提价或修改原价。模板保持产品、sku、调价动作、折扣价格；动作可留空。选择店铺、上传和检查后，默认只读；确认“实际调价”的三种操作范围才提交。旧任务保留原操作范围，需重新上传新建三种混合批次。

1. 锁定店铺配置和实际登录卖家，按店铺串行处理。每店只持有一个自建工作标签，后续SKU复用；关闭时只关闭程序自己的标签。
2. 展开分组、精确匹配SKU或已确认商品ID；同一精确SKU多个商品分别拆开，完全相同重复记录合并。身份、活动、原价不明不提交。
3. 按实时活动价比较目标，低则直接修改，等则跳过，高则在符合原价折扣范围后，打开原活动修改框、停止参与并二次确认退出、刷新确认退出，再报名同一原普通活动。无活动可报名唯一非新提案普通活动。
4. 第三种：目标超出原价20%–95%时，退出当前唯一已确认普通或补贴活动，再直接将商品原价改成表格目标并结束，不再报名。原价已达目标只退出仍生效的活动，活动价已达目标则不操作。平台还有其他价限时保留原因，不擅改表格目标。
5. 只填写主促销价或指定子商品原价，不选择新提案，不勾选额外折扣、广告、自动定价或“应用于所有变体”。退出确认、报名与原价保存各自提交前持久化原绑定、旧价、原价、目标、报价和阶段，记录失败不提交。
6. 重新加载核验商品及目标。活动改价要求原活动与原价一致；第三种要求原价等于目标、没有生效活动，并独立在商品管理核实售价。不能把弹框关闭当成功。
7. 失败继续其他SKU，最多3轮。结果未知先读：已到目标不重复保存；退出结果未知不重复退出；报名结果未知只有两次新读数和原报价一致且无活动时才单次重试报名。已完成不为凑轮数重跑。退出后报名失败可能暂时没有活动，须明确提示并保留记录。
8. 暂停在当前行结束后生效；服务中断不自动恢复。关闭网页服务继续，完全退出需要停止本地程序。支持美客多巴西站，其他站点不纳入。

## 标签数量与执行边界

正常执行最多同时持有一个程序专用工作标签：店铺 A 内串行处理所有 SKU → 关闭自有标签 → 店铺 B 新建一个。几十个 SKU 不需要几十个标签。紫鸟或美客多自己已有的首页、商品页等仍可能存在，因此浏览器总标签数不保证为一。

程序仅关闭自己创建且持有明确目标 ID 的标签，不清理历史调试标签和用户已有页面。客户端崩溃或强制结束进程时清理可能来不及完成。

当前支持巴西站已有活动升降价、普通报名，以及确认新任务范围后的第三种改原价。执行前核对所选紫鸟配置与登录卖家，执行中避免同时手工操作同一店铺。触发验证即暂停整批并显示 Windows 独立置顶弹窗；人工验证后点击继续，再回读原提交状态。关闭弹窗或稍后处理保持暂停。

## 0.4.14 第三种流程修正
折扣不足5%（包括目标高于原价）：退出活动后原价改为目标价，不重新报名。折扣超过80%：退出活动、原价降为目标价的4倍、报名普通活动并设置目标价，最终75%折扣。每次写入前保存阶段，恢复先回读；无普通入口或审核异常保留真实原因。
