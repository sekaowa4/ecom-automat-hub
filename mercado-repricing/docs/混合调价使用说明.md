# 混合调价使用说明

0.4.20支持同一张表自动执行降价、提价、修改原价，不必拆表。保留标准模板四列表头：产品、sku、调价动作、折扣价格。调价动作可以填写提价/降价或留空，只作为表内记录；实际方向按所选店铺实时价格与目标价比较。没有调价动作列也支持，仍需SKU和目标售价。

1. 打开紫鸟并登录店铺，在程序选择店铺，上传整张价格表，检查数据。表中不需要店铺、站点列。
2. 默认只读，不改价格。执行时选择“实际调价”，核对店铺范围和当前登录卖家，勾选混合调价确认后开始。
3. 低于当前活动价：直接修改原活动价格；高于当前活动价：先退出、确认退出，再重新报名同一个原活动。相同价格跳过。没有生效活动时可以报名唯一非新提案普通活动。
4. 第三种分两类：目标高于原价95%（折扣不足5%，包括高于原价）时，退出活动后直接将原价改为表格目标价，不再报名。目标低于原价20%（折扣超过80%）时，先退出当前活动，将原价降低为表格目标价的4倍，再报名可用的普通活动并设置表格目标价，最终折扣为75%。例如原价169、目标18.90，先将原价降为75.60，再设置活动价18.90。表格目标不改变；退出、原价、报名分别记录并核验，不选择新提案或已预约活动。平台审核未激活、无普通活动入口或其他价限仍明确提示，不能伪造成功。已提交的旧版计划保持原提交绑定，不转换历史记录。
5. 精确SKU对应不同商品ID时全部拆开执行并分别核验；完全相同的页面重复记录只处理一次。分组展开到精确子商品；无法确认身份、活动或原价时不提交。
6. 普通活动提价退出后重报原活动。0.4.16新建实际任务确认后，若补贴或秒杀阻挡目标价，可退出该活动并转报已绑定的普通活动；旧任务不自动扩展退出权限。第三种可退出当前唯一普通或补贴活动。不选择新提案，不勾选广告、额外折扣、自动定价或“应用于所有变体”。每店复用一个专用工作标签。
7. 失败项先跳过并继续其他行，最多处理3轮；完成项不重复执行。提价分别记录退出、报名阶段：退出结果未知只回读，不再次退出；已到目标不重复报名；报名结果未知且两次新读数均一致、原价和报价均未变时才允许单次重试报名。
8. 退出后若报名未完成，商品可能暂时没有活动。程序在结果中明确提示并保留原活动、旧价、目标和提交阶段，不能把它当成功。遇到需人工核对项请按说明处理。

旧任务保留原操作范围，升级后不会自动获得改原价权限。需要三种混合调价时上传整表新建批次，确认内容包括退出活动和按表格目标修改原价。服务中断不自动恢复原任务；先查看提交阶段与实际价格，不要直接反复启动旧脚本。程序包不包含他人账号、历史任务或个人店铺测试记录。

触发验证或登录页时整批暂停，显示 Windows 独立置顶警示弹窗并播放提示音，标明店铺和 SKU；网页关闭时仍可提醒。请在紫鸟完成验证后点击“我已验证，继续调价”。未验证通过会再次等待；关闭或选择“稍后处理”保持暂停，可在工作台恢复。等待状态持久保存，预提交验证不消耗三轮重试次数，已有提交记录保持，恢复时先回读，不盲目重复提交。不读取或代填验证码。原价保存结果未知时先重新读取：已达目标不重复保存；原价已被改成第三个数值、出现新活动时不覆盖，保留核对原因。CSV追加原价提交阶段和改前原价，页面“当前售价”可显示活动价或无活动时的原价。

0.4.8更新：提价不再以固定0.5秒判断编辑框是否已打开，而是等待弹框、主价格和停止按钮就绪。超时明确指出所处步骤，不再把尚未加载误报为弹框不唯一。退出与重报的价格、商品、原价、活动和单次提交校验保留。

0.4.11：旧式无SKU标签商品通过详情页确认SKU后整商品统一调整，同批关联SKU目标冲突时拦截。只处理激活活动，已预约周末活动保持原状。重复展示只比较调价关键字段；分组等待实际子商品加载；促销中心不返回的商品转商品管理独立回读实际价格与平台状态。

0.4.11 外观更新：原浅色配色保留为默认，可在侧栏底部开启黑色与荧光绿护眼模式。统一调整字号、图标、表格与窄屏布局；不改变调价流程和任务范围。

0.4.12：新增人工验证等待与 Windows 独立弹窗；修复商品主编辑入口与批发价/分期入口混淆；退出后暂时缺少商品时保留退出记录，下轮先回读。补贴活动提价仍需单独确认规则，平台审核未通过等真实限制保留明确原因。

0.4.13 外观更新：原两款配色保留，护眼开关改为调色盘图标进入皮肤中心；新增6款皮肤及自定义。支持本机浏览器保存自选背景图、面板透明度和磨砂，网页透明仅透出背景图片。旧护眼选择自动沿用，调价权限、流程和历史记录不变。

0.4.14：修正折扣超80%的处理；降低原价后设置折扣价，按75%反算新原价。导出追加计划新原价与重新报名活动ID。中断后按保存阶段先回读，禁止重复退出或盲目重复保存。

审核未激活的商品始终保留“待核对”及具体审核原因；即使读到目标价格，也不标记成功或跳过。程序不自动修正品牌/审核信息，不对审核未通过商品强行改价或报名。

0.4.16：展开分组后识别实际子SKU，激活状态不受11.11徽标顺序影响；兼容只读现价的秒杀退出弹框；原价编辑受批发价格阻挡时，关闭批发价格、确认保存并刷新复核后再改原价。旧式多规格商品保留规格名称，单一变体改原价不能连带覆盖整链接；仅本批覆盖全部关联SKU且目标一致才允许父链接统一修改。普通活动已预约但未激活仍列为待核对，不重复报名。退出后平台如接替生效另一活动，先保留记录回读，不盲目连退。

0.4.17：修复确认退出补贴后，同一精确SKU的多个商品无法拆分的权限兼容问题；子行保留原表字段，任务授权统一继承，不能改动目标或扩大范围。卖家自建百分比折扣未返回平台活动编号时，使用程序内部类型标识，核对商品、唯一激活状态、折扣名称、日期、原价、当前价；降价直接改，提价退出后报名唯一普通活动。内部标识不是平台活动ID，不推断未知活动。日期在主活动与可选折扣列重复展示时核对相同日期；冲突仍拦截。其他缺号活动先重新加载核对；校验失败显示原始保护原因，避免同一内部校验异常空耗三轮。

0.4.18：修复1006-1031与6至31/10月粘连导致普通活动报名误判；合并刊登行按行内编号定位，销售条件多价格区块按MLB编号绑定，只有目标价格变化且同页其他商品价格/选项不变才允许共用确认保存。已确认退出授权且原页面已记录的预约自建折扣在退出后接替生效时，核对同一商品、原价、活动日期与旧价，最多追加一次退出；两次退出与转报分别持久化，不处理未知接替活动。保持3轮，已完成不重跑；弹框60秒、页面读取210秒、原价准备240秒、保存后核验180秒，控件就绪即继续。页面主体可交互且商品与控件校验齐全即可读取，不等待无关资源全部完成。增加等待不能代替修复活动校验或商品定位错误。

0.4.19：处理页面已显示但按钮尚未响应的卡顿。打开编辑框等待期间，15秒与40秒若仍无编辑框，可重新核对商品、原价、现价及活动入口后重开只读编辑框；不重复退出确认、不重复保存价格。若出现多个编辑框或绑定变化则立即拦截。保留3轮业务重试及0.4.18延长等待设置。

0.4.20稳定性整理：三种流程共用最终售价核验，必须身份、阶段原价、实际售价、唯一生效活动和审核状态同时满足；多个活动仍生效时不能仅凭普通活动目标价报告成功。活动名与弹框主活动解析共用一份代码，统一等待策略仍保留3轮。分组逐个子商品检查，不因第一个加载成功就漏掉慢子商品。历史场景记录于tests/regression-manifest.json，发布自动运行全部回归，失败禁止打包。本版维护不自动调价、不重跑历史任务，验证、审核及不可确认身份仍按真实原因待核对。


## 0.5.32 已知未提交调价恢复

上一批中仅重排可由阶段和原始日志证明未完成商品价格保存的单笔运费确认项，以及明确显示未提交价格的商品列表展开超时项。保留原目标价、商品编号和提交检查点；每行先回读实际原价、活动状态与价格，已达标的不重复提交，状态冲突的继续列待核对。完成行和其他原因的待核对行不进入恢复队列。
## 0.5.33 已回读折后原价的断线恢复

仅当批次日志记录了折后原价保存及最终价格核验、随后明确在“打开活动”阶段断线，且最后回读确认原价等于本表目标价四倍、指定普通活动仍可报名且尚未激活时，才允许从既有调价检查点续跑。恢复时仍重新读取商品和活动；其他连接失败继续待核对，不自动重试。
